## Debt policy and sequencing

1. Treat migration/seed safety, production email configuration, upload delivery, queue lifecycle, and consent handling as release blockers until owner-confirmed deployment tests pass.
2. Do not repair migration history by editing already-applied migrations until the owner provides migration state and approves a staging comparison/backup plan.
3. Keep enterprise feature work (profiles, RBAC, broad audit logs, advanced analytics) behind product decisions; do not expand architecture to solve unconfirmed requirements.
4. Preserve current strengths—typed environment parsing, shared admin checks, upload scanning hooks, moderation history, and CI checks—while closing gaps incrementally.

## Authorized follow-up status

The owner separately authorized the subscriber-consent finding after the baseline review. New public signups now require a signed, expiring email confirmation before campaign eligibility; legacy `granted` records are excluded pending owner-approved reconfirmation. This removes the runtime consent gap for new intake but does not resolve console-email delivery configuration or audit historical consent evidence.
